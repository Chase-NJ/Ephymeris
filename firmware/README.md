# `libraries/` — the shared Arduino library folder

This repo root's `libraries/` folder is the **one** place shared sketch code
lives. The Ephymeris sidecar passes it to `arduino-cli` as
`--libraries <repo>/libraries`, so every sketch can `#include` anything here with
no per-machine setup (`arduino-directory.md` §4). The Arduino IDE finds it too,
as long as its sketchbook is set to this repo root.

> This folder **is** tracked in git. A previous layout kept the shared header in
> a nested `Olfactory Behavior/02_Bdisc/libraries/` and reached the root via a
> symlink — but the sidecar only ever passes the *root* `libraries/` to
> `arduino-cli`, and symlinks are fragile on the Windows lab machines. The real
> folder here replaces both.

## `BehaviorBox/BehaviorBox.h`

The single shared header for **every** sketch — the GRGL task, the simulator,
and the utility/cleaning sketch. It is the one source of truth for:

- the **serial protocol** helpers shared with the app: `emitStrobe`,
  `readLineInto` (await `START`), `checkForStop`, and — for utility sketches —
  `CommandReader` (non-blocking command parse) + `emitStatus` (non-persisted
  `STATUS` telemetry);
- `TaskParams` and `TASK_PARAM_LIST`, the one declarative list the `START`
  parser is generated from;
- the reusable **trial primitives** (`TrialClock`, `TrialType`, `TrialWeight` +
  `generateTrials`) and the **session policy** classes (`AntiBiasSelector`,
  `AbstentionPenalty`, `CorrectionPolicy`);
- the **trial runner**, so a weighted pool and live anti-bias selection are one
  loop that differs only in which policies it is handed.

A sketch includes it with angle brackets:

```cpp
#include <BehaviorBox.h>
```

### `BoxPins.h` and `BoxStrobes.h` — the box, and how a profile overrides it

The pinout lives in `BoxPins.h`, and **every definition in it is
`#ifndef`-guarded**. A sketch that includes a generated `TaskPins.h` *before*
`<BehaviorBox.h>` overrides whichever pins it declares and inherits the rest:

```cpp
#include "TaskPins.h"     // generated by Ephymeris: pins, strobes, counts
#include <BehaviorBox.h>
#include "TaskTrials.h"   // generated: the trial table. Needs TrialType.
```

That is the whole mechanism by which a task profile authored in Ephymeris — the
channel→pin map, the trial table, how many ramp stages exist, which selector
runs — reaches the firmware.

**The `BF_*` strobe codes are not in this repository.** Ephymeris keeps one
vocabulary per machine and writes every live code into each `TaskPins.h` it
generates (Ephymeris `docs/TASKS.md#strobe-vocabulary`). `BoxStrobes.h` defines
none and stops the build with an `#error` when they are missing, so a sketch
must be built from a folder the app generated — `<app data>/rig/sketches/…` for
a bundled sketch, `<app data>/tasks/…` for a saved task. To emit a new code, add
it on the app's Strobes page first, then name it `BF_<NAME>` here. The host
tests use `extras/host_test/strobe_fixture.h`, whose numbers are deliberately
not the lab's.

### Compiling in the Arduino IDE (optional, for editing/checking)
IDE 2.x scans exactly one user library folder, `<sketchbook>/libraries`. Set the
sketchbook to this repo root (File > Preferences > Sketchbook location) and the
IDE picks up `BehaviorBox` with no symlink. Restart the IDE afterward so it
rescans.

Or compile with the library path passed explicitly. Point it at a folder the app
generated — a sketch here, built bare, stops at `BoxStrobes.h` because the strobe
codes are not in this repository:

```bash
arduino-cli compile --fqbn arduino:avr:mega --libraries libraries "<app data>/rig/sketches/Olfactory Behavior/GRGL"
```

> [!CAUTION]
> **`arduino-cli compile` will not tell you about a type error.** The AVR core
> builds with `-fpermissive -w`, so passing (say) a `const TrialType*` where an
> `int` is expected is a *warning*, and the build suppresses it: you get a size
> report and exit 0 on code that is wrong. This is not hypothetical — it is how
> `GRGL_Sim` kept compiling against a changed `AntiBiasSelector` signature while
> reading a truncated pointer as a trial count.
>
> After changing anything shared, compile every sketch with `--warnings all`
> **and** run the host tests below, which use no `-fpermissive`.

### Host compile-check (logic only)
`BehaviorBox/extras/host_test/run.sh` compiles the header off-target against a
minimal `Arduino.h` shim and exercises the policy classes
(`parseStartCommand`, `CorrectionPolicy`, `AbstentionPenalty`,
`AntiBiasSelector`, `generateTrials`). It does **not** replace flashing to the
rig — only `arduino-cli` does the full AVR compile. It *is* the strictest type
check these sketches get, for the reason in the caution above.

```bash
sh libraries/BehaviorBox/extras/host_test/run.sh
sh libraries/BehaviorBox/extras/host_test/run_box.sh
```

On a Windows machine with no clang or gcc, the MSVC Build Tools compile both
unchanged — each script's header carries the `cl` line.
